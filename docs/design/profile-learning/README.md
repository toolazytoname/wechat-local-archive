# 下一阶段：画像与稍后读（设计冻结稿）

**状态：仅设计，不代表功能已经实现。** 当前产品源代码、真实档案、桌面运行服务均不因本规划改变。用户将自行把任务交给另一个模型，规划阶段不要创建执行代理。

## 先读哪些文件

1. `product-spec.md`：产品定位、页面、交互、画像边界、学习流程、设计规范。
2. `implementation-contract.md`：已有模块、数据模型、接口、任务拆分和验收。
3. `prototype.html`：可直接用浏览器打开的纯虚构可点击设计稿。没有真实分析或远程请求。
4. `handoff-prompt.md`：给下一模型的启动指令。
5. **本机专属补充**：`data/planning/profile-learning/private-context.md`，存在时只在本机读取，不复制到公开仓库、日志或外部模型请求。

产品、工程文档都是下一阶段的约束，不是现状报告。每次交付必须区分：设计完成 / 合成测试通过 / 本机真实验证 / 仍待授权或配置。

## 不得改变的三条产品决定

- 画像是**基于所选记录、能回到原文的资料与观察**，不是心理测评、人格判定或关系评分。
- 稍后读中的文章、转发与他人观点，**不能直接变成本人观点**。
- 分析计算及派生内容默认留本机；云端分析与网页取回必须有独立、具体的用户动作，不能把“本地工具”悄悄变成默认上传工具。

真实聊天、人物关系、本机账户 ID、密钥、私有分析结果不进入这个公开设计目录。原型里的所有人数、日期、引文、主题和关系均为虚构示例。

## 设计稿验证（不是产品功能验收）

纯虚构原型已在1440/1280/1024/390/320五种宽度检查20个页面布局；检查了证据抽屉与Esc焦点返回、好友资料不足状态、标题-only禁止摘要、阅读/笔记示例状态及复习答案展开。无自动HTTP请求。设计稿笔记仅保留在页面内存，刷新即清空；正式版必须有真实本机持久化。

规划只交付文档和原型：没有生成人物画像，没有整理真实学习条目，也没有配置/调用真实分析引擎。
