# 产品设计：了解自己、了解交流对象、把收藏变成学习资料

## 0. 设计目标与范围

目标用户是使用自己 Mac 的普通人，而不是数据库工程师。原有微信聊天档案是底座；新增“我的画像”“好友画像”“稍后读”，但不牺牲聊天、附件、搜索及导出。

**设计解读：消费级本地知识工具；沿用微信灰白与绿色，阅读区更清爽，交互少而明确。** 变化强度4/10、动效2/10、信息密度4/10。原型作为布局、层级、配色和关键交互参考，不是要求开发者照抄原型的内联代码。

本版不是社交关系侦察、自动给联系人贴标签、心理诊断、推荐操纵别人，也不增加另一个无边界聊天框。没有证据或配置时不生成“看起来很完整”的假报告。

### 首版必须闭环

1. 确认“我是谁”和所选会话用途。
2. 生成并查看一个有范围、有证据、可纠正的本人画像。
3. 选择一个好友，查看基于对方本人发言的资料与交流观察。
4. 把一个收藏群整理成可读、可笔记、可复习、可导出的学习库。
5. 所有结论能回原文，派生结果可以删除，原始记录不可被覆盖。

### 暂不做

跨平台新取钥、V2图片解密攻关、社交图谱、MBTI/大五雷达图、关系亲密度/爱意/忠诚分数、健康/政治/宗教等敏感属性推断、情绪或精神疾病诊断、读心、全自动抓网页、付费墙绕过、云同步、跨用户共享、全自动OCR/语音识别、自动发微信。它们不是首版完成的依赖。

## 1. 基于当前页面的改造审计

当前首页主要用于选择档案和启动导出；聊天页是会话列表+聊天内容，信息架构以档案和读取流程为中心。已有灰白底、绿色发送气泡、中文系统字体、简单按钮与抽屉。这些熟悉的聊天呈现应保留。

现有 `static/index.html` / `app.js` 没有画像、阅读库或分析引擎。不得只在首页追加三张巨大卡片，然后把实际操作藏进弹窗；也不要推倒现有安全服务和导出器重写成另一套框架。

**保留：** 会话搜索、上下文定位、图片放大/文件下载、日期分页、导出范围预览、原厂微信不被改动的边界。

**调整：** 加一层跨功能导航和统一的档案范围栏；把首次读取放进“档案与设置”；分析长任务单独有状态页；设置只在需要时展开。不要将账号路径、SQLCipher、source revision 等技术词放到默认页面。

## 2. 信息架构

```
微信聊天档案
├─ 聊天档案              原聊天列表和消息流
├─ 我的画像              范围概览 / 画像报告 / 变化记录 / 我的补充
├─ 好友画像              搜索好友 / 选择对象 / 对方资料与交流观察
├─ 稍后读                收件箱 / 主题 / 阅读器 / 笔记 / 复习
├─ 导出数据              原有导出 + 画像报告 + 学习资料包
└─ 档案与设置            选择档案、身份、分析方式、隐私、读取新记录
```

不要再加一个没有明确用途的“AI助手”一级导航。全局范围栏显示“当前档案 · 记录截至日期”，切换档案后不混用旧报告。退出页面不取消任务；有任务时导航底部出现“正在整理：已处理…”，可进入查看、暂停排队或取消。

桌面优先记住上次使用的板块；首次打开仍能直接看聊天。手机样式只保证窄屏浏览，不宣称可在手机上读取微信。

## 3. 一次性身份与上下文确认

### “我是谁”

从已有 `is_self`、账号映射及 sender ID 建立候选，不能按显示名、最多发言者或妻子称呼推断。若已有映射足够一致，显示简短确认卡；缺失或冲突时必须停止画像、让用户选对身份，不能静默把好友当本人。导出原始记录保持不变，修订只写派生元数据。

### 人物和会话用途

用户补充的关系放在私有元数据：对象稳定ID、关系、说明、来源=`user_provided`、确认时间。显示名只是别名，重名不自动合并。

用户可将会话标成“日常聊天 / 收藏学习 / 工作协作 / 暂不参与分析”。收藏群默认作为学习资料来源，不参与本人性格或观点推断。用户在收藏消息上自行写的评论可以作为本人表达，但转发文章正文仍归原作者。

本机已有明确的用户背景见私有补充文件；公开演示使用完全虚构的对象。

## 4. 我的画像

### 页面结构

- 顶部：`我的画像` + 一句说明“从记录里看见自己，而不是被一个标签定义”。右侧主操作 `生成画像` 或 `更新画像`；次操作 `导出`。
- 范围条：时间、已选会话、覆盖消息数、缺失附件情况、是否抽样。不要用“完整了解你”或总分。
- 默认正文为4–6个编辑式章节，不做20个指标卡：
  1. 最近在关注什么；
  2. 明确提过的目标、项目与计划；
  3. 兴趣与学习轨迹；
  4. 沟通方式的场景观察；
  5. 相比早期有哪些变化；
  6. 还不能判断什么 / 想补充什么。
- 右栏：用户补充、资料范围、来源分布、限制；不重复正文结论。
- 各章节可折叠。默认先给短结论，展开再读细节。

### 一条观察长什么样

```
近两个月，你多次提到想把阅读笔记整理成文章。
[记录中的观察]  3个时间段 · 2个会话（示例）
依据：你本人发言；未采用转发正文。
[查看3条原文] [补充/纠正]
```

不要写“你是一个执行力85分、天生焦虑的完美主义者”。不使用模型自报的百分比置信度。UI区分：`你补充的信息`、`可核对事实`、`范围内观察`、`资料不足`。

### 不停留在主题统计，但也不“读心”

画像应在有依据时进一步回答：你如何把问题变成行动、做决定时经常要求什么信息、什么目标反复出现、在哪些场景常用某种沟通方式，以及哪些地方值得你自己反思。例如“这几个项目里，你通常先要求一个具体样例再决定下一步”，比“你是视觉型决策人格”更有用也更可核对。

可加入“做事与思考的习惯”“明确表达的优先事项”“可尝试的改进”作为有证据时才出现的章节。建议与事实必须分开：观察到多次计划并不能证明缺乏执行力；没有记录完成不等于没有完成。反思问题可写“你想核对这些计划后来怎样了吗？”，不要替用户给出道德评价或诊断。

### 点击“生成/更新画像”

一个浅显的准备页，分为“看哪些资料”与“怎么处理”，不是十几个参数：

1. 默认最近12个月（这是产品起点，不是科学阈值）；一键切换全部、最近3个月、自定时间。
2. 会话按用途分组。收藏群默认排除；家庭/工作等可选；明确展示是否某个会话占比过高。
3. “本人发言是画像证据；其他人的话只作上下文”固定提示。
4. 显示实际覆盖/抽样策略、预计处理量和引擎状态。不可用时提示缺少什么，不输出演示报告。
5. 云端处理必须先展示提供方、发送字段、数量/估算量、附件是否发送、预算上限；具体批准本次任务后才联网。没配置引擎仍可查看**资料概览**和导出证据材料，但不能把它标成已生成画像。

### 家庭聊天偏多的处理

同一长期会话的重复内容不能按条数制造“强证据”。按会话、时间段、场景分层总结，显示覆盖分布。仅家庭来源支持的结论写成“在家庭交流中…”，不能推广到职业能力或整个性格。不要为凑平衡丢弃大量记录却隐瞒抽样；统计尽量覆盖完整范围，叙述分析若抽样必须标明实际覆盖。

### 更新、纠正和撤回

- `补充/纠正`：选择“事实不对 / 当时情境不同 / 不想用于画像 / 补充说明”；写入用户修订，不修改消息。
- 排除的证据在下一次更新中不再使用；旧版本显示该观察已被用户修订，不能悄悄继续引用。
- `变化记录`比较两个相同口径或明确不同口径的报告；范围不同不能声称人已经变了。
- 删除报告只删除派生报告，不删聊天；删除私有分析资料时说明缓存、嵌入和派生索引的范围。云端已发送的内容无法靠本机删除撤回，要明示。

## 5. 好友画像

### 入口与布局

左侧为好友选择/搜索（只显示可用会话，不自动分析整个通讯录）；右侧为当前好友。没有选择时显示说明与搜索，不显示某人的假数据。

首版默认只用“我与这个好友的一对一聊天”。群聊扩展是显式高级选择，未验证群 sender 映射前不开放。切换好友必须清空上一位的正文、证据与下载状态，防止串档。

章节：
1. 对方自己明确说过的信息（用户补充另列来源）；
2. 反复谈到的兴趣、需求和近期事项；
3. 你们的共同话题与未完成约定；
4. 对方明确表达过的沟通偏好；
5. 可回到原文的交流观察与信息缺口。

对伴侣可以写“你们共同安排过的事情”“对方明确提出的期待”，**不要新增关系评分、感情趋势预测、谁更爱谁、出轨可能性**。关系是用户确认的背景，不是分析模型“发现”的结论。

### 归属约束

对方资料只用对方本人的发言做证据。我说“你很喜欢X”不等于对方确实喜欢X；转发、引用、玩笑、反问、否定、替别人转述不可直接提炼为稳定偏好。我的话可显示为“你对对方的描述”，不能偷换来源。

报告标题可用“关于TA：基于与你的交流”，而不是“TA的真实人格”。对象未明确自述、用户未补充的健康、宗教、政治、性取向、资产等敏感属性不推断，也不进入默认章节。信息多不等于获得了诊断或判断别人的资格。

## 6. 稍后读：本版重点独立板块

### 正确的内容分类

学习条目可以来自：网页卡片、正文里的网址、用户自己保存的长文本、文件、图片、视频、语音占位、带评论的转发。收藏群中的聊天消息原样保留为来源，不当成文章正文。

一个消息可以拆出多个条目，一个条目可以有多个收藏来源；相关前后评论可作为备注，但不自动拼成文章。重复收藏合并条目时必须保留每次收藏的时间、message UID 和用户评论。

阅读状态与内容可用性是**两组不同字段**：
- 阅读：`待整理 / 待读 / 在读 / 已读 / 已归档`；
- 内容：`只有标题 / 有正文 / 部分正文 / 登录或访问失败 / 附件缺失 / 加密不可读 / 格式不支持`。

“已抓到正文”不等于“我已读过”；打开阅读器不自动标记已读。

### 首页 / 收件箱

顶部标题 `稍后读`，副标题“把存下来的东西，变成真正学到的东西”。主操作 `整理收藏群`（首次）/`更新收藏`（之后），次操作 `导出学习资料`。

左侧窄栏：收件箱、待读、在读、已读、我的笔记、复习；下方为用户可编辑主题。中间是**简洁列表**而非满屏网页缩略图：标题、来源域名/类型、收藏日期、正文状态、用户备注。没有真实封面就不要伪造封面或生成假图。

搜索覆盖标题、已有正文、个人笔记；检索命中范围可辨。筛选主题、来源、阅读状态、内容状态。默认按收藏时间，新旧排序可换；不要未经请求按“与你性格匹配度”排列。

### 阅读器

双栏：左为文章，右为“梳理 / 我的笔记 / 复习”；窄屏变顶部标签。主阅读列约680–760px上限，正文16–18px、行距1.75–1.85。

顶部保留来源、收藏时间、原文链接、正文取得时间及完整性。只有标题时展示标题和本人的收藏备注，明确“尚未读到正文”；`概括正文`不可用。允许 `打开原文`、`粘贴正文`、`导入本地文件`。通过按钮请求网页取回是后续受控操作，不默认全量访问群里所有链接。

取得可验证文本后，“梳理”包含：
- 30秒概览（3–5点，非硬凑）；
- 作者的核心主张；
- 概念与术语；
- 论据、例子及作者没有回答的问题；
- 可选练习或行动（标为建议，不能伪称文章原文）；
- 相关收藏及关系说明。

文章摘要引用段落，跨文章归纳列出支持/冲突来源。作者观点、我的评论、系统建议三种来源分开呈现。没有读到正文就不能写“本文认为…”。图片只可看预览时不假装完成OCR；语音未转写就不做语义总结。

### 笔记与复习

选中文本 → `摘录并记笔记`，保存原文版本、段落/文本范围及引用摘要。用户笔记用自动保存状态“已保存到本机”，切换条目或刷新不丢失；分析刷新不覆盖用户笔记。

读完后人工点 `标记已读`。可选择3个理解问题、概念卡和“用自己的话解释”的开放问题；先遮住参考答案，再展开，来源可点。首版手动加入复习、今天复习即可，不加伪精确掌握率、连续打卡压力或后台通知。

主题页将同主题材料归纳成“入门 / 深入 / 实践”的可编辑建议顺序；每一步解释为什么放这里。少量材料就显示少量，不为了凑课程虚构章节。题库、测验分数与遗忘曲线自适应推迟到后续。

### 给用户的一份学习导出

首版必须先交付一个**不用配置LLM也能使用**的整理版：真实标题、用户备注、来源、可用正文/附件、主题待整理标记。随后增加有证据的摘要与复习内容，不能为了等模型把最基本的学习资料导出卡住。

```
学习资料包/
  开始阅读.html             离线目录，搜索、主题、来源与可用状态
  先读我.md                 范围、限制与使用方式
  目录.md
  items.jsonl              条目/主题/来源/阅读状态，原始消息UID可追踪
  articles/<item_id>.md     可用正文、备注、段落编号
  summaries/<item_id>.md    仅实际完成且验证通过的摘要
  notes/                   用户选择包含的笔记
  review/                  用户选择包含的复习卡
  media/                   真正可用的本地附件
  manifest.json
  SHA256SUMS
```

离线HTML必须不依赖本机端口，不自动连接原站、不执行原文脚本；“打开原文”是明确点击。保留一份JSONL供其他工具处理；不叫“给AI的导出”。主题学习资料和原始群聊天导出是两种互补产物，后者不能被替换或丢弃。

## 7. 证据、引用与内容安全

每条画像观察引用至少一个可解析的原始来源；概括性的模式观察还需要多个时间段/上下文支持。多条相邻聊天、同一转发重复出现不算多份独立证据。产品不能把这些经验门槛包装成科学有效的心理量表。

点引用打开右侧证据抽屉：本人/好友角色、时间、短引文、必要上下文、选取理由、`在聊天中查看`。必要上下文按窗口读取，不能点击一条引用就把整个私聊批量传给服务商。回到聊天后保留原滚动位置和来源抽屉返回入口。

用户/聊天/网页/附件里的提示词均是待处理内容，不是系统命令。模型不能自行访问网页、运行命令或获得系统文件读取权限。所有模型输出用安全DOM或经白名单处理的结构化块渲染，不把返回Markdown当不受限HTML插入。

画像和学习摘要不能改变基础档案的 `source_kind=live-db` / `backup2_coverage=unverified`。派生结果附带范围和生成版本，不能被误认为原始聊天事实。

## 8. 视觉与交互冻结

| 项 | 规范 |
|---|---|
| 背景 | #F4F6F2；白色阅读面；不做深色科技大屏 |
| 文字 | #202B24；次级#5E6A61，淡色不用于正文 |
| 强调 | 深绿#286448；聊天发送气泡保留现有浅绿 |
| 提示 | 柔和琥珀，用于资料不足/未取得正文，不用大片红色 |
| 字体 | macOS中文系统栈；无外部字体请求 |
| 大小 | 页标题28，章节20，正文15–17，元信息12–13；阅读正文16–18 |
| 间距 | 4/8/12/16/24/32/48；卡片内20–24 |
| 容器 | 全局侧栏184；工作区可伸缩，正文宽度受限，不沿用聊天页1100px硬上限包所有新页面 |
| 圆角 | 常规10–12；阅读面14；不满屏胶囊按钮 |
| 动效 | 120–180ms淡入/滑入；支持reduced-motion，无循环动画 |
| 主要操作 | 每个页面一个主按钮；危险删除与生成不相邻 |

宽度≥1200：画像正文+范围侧栏；证据抽屉覆盖而非再挤出第四列。768–1199：侧栏收窄、附加信息折叠。窄屏≤767：单列、底部简化导航或可访问菜单；好友选择/学习列表/阅读器逐层进入，有明确返回。必须检查1440、1280、1024、390、320五种宽度。

所有图标同时有可理解标签或accessible name；按钮有焦点样式；弹层Esc关闭、焦点圈定并归还触发按钮。搜索300ms左右防抖并取消/丢弃过期请求。加载显示真实任务阶段与计数，不造进度百分比。空态、引擎未配置、读取失败、取消、资料不足、过期报告都要设计，不只画成功页。

## 9. 成品判定

用户不用开终端即可：选择本人/好友范围 → 知道资料是否会出本机 → 得到可回原文的结果或明确的未生成状态 → 修订/导出。收藏群可以变成独立可携带的学习包，离线打开可读内容、打开附件并识别缺失。

界面“精美”不等于截图上有数字、图表和动画；以阅读舒适、少步骤、可追溯、不会丢失笔记与上下文为验收标准。
