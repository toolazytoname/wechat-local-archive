# 本地附件恢复与展示

## 范围与边界

只从用户已授权的本机账号媒体目录、已解密的同一快照映射库中读取，写入导出档案自己的 `media/`。不启动微信、不取新密钥、不改变原始媒体、不访问远端 CDN。来源仍为 `source_kind=live-db`，`backup2_coverage=unverified`。

这不是“全部附件已恢复”：加密原图、没有缓存的文件、语音、表情和转发消息内嵌附件仍有缺口。文字导出和二进制附件恢复是两个独立步骤；以前生成的 ZIP/离线 HTML 不会自动更新。

## 为什么之前只有卡片

聊天正文里的图片/文件描述并不是实际文件。原导出不带媒体目录，而本机媒体文件名也不总是消息 XML 内的 MD5。只根据标题、文件名或邻近时间猜附件会错配，尤其是重复文件名和跨会话内容。

## 可验证的关联

1. 图片/视频优先用 `MessageResourceInfo`：会话身份、服务器消息 ID、消息类型一起关联；有符号服务器 ID 统一为无符号 64 位表示。
2. 当前适配器只接受观察并测试过的 `packed_info` 结构：protobuf 字段 2 嵌套字段 1，内容为 32 字节十六进制资源名。未知布局拒绝，不扫描任意字节猜资源名。
3. 图片再限制到该会话哈希目录的 `Img` 子目录。
4. 明确声明的 MD5 可走 hardlink 映射；文件附件必须再核对实际内容 MD5。文件名相同不算证据。
5. 可读预览优先于不可读加密容器；有真实视频则优先视频而非封面。

## 存储和服务

- 源文件只读、拒绝符号链接穿越；读取前后核验文件身份、长度与时间戳。
- 内容按 SHA-256 寻址，去重保存。私有 SQLite 索引记录消息关联、MIME、大小、摘要与原图/预览状态。
- 完成前写临时目录，验证原始正文与映射库没有变化，再原子发布。已有媒体目录不会覆盖。
- HTTP 绑定具体档案，验证内容摘要后流式读取，支持 Range。文件强制下载，避免将任意附件作为站内活动文档执行。
- 图片支持查看大图、下载；视频封面不是可播放视频。缺失状态明确显示。
- 不自动发起外部请求。公网分享和数据上传不属于恢复过程。

## 验证

`tests/test_recovered_media.py` 使用纯合成图片、文件、映射库，检查准确关联、预览降级、原文件不变、错误文件拒绝、跨会话拒绝、摘要篡改拒绝，以及 HTTP 下载/Range/档案绑定。

`tests/browser/recovered-media.cjs` 用真实浏览器验证图片解码、大图、文件下载及零外部请求。不能用 HTTP 200 或 JPEG 文件头替代浏览器解码验证。

普通使用说明见 [consumer-guide.md](consumer-guide.md)。本机恢复数量、源路径和内容清单只保存在被忽略的私有档案中，不进入公开仓库。
