- 账号选择使用独立单列组件，档案卡使用独立双列/小屏纵向组件，不再错误套用聊天列表grid。
- 首次读取面板按需展开，环境与兼容性放在折叠详情；快照选择放高级选项。
- 普通用户不用在首页阅读原始路径、快照ID、LLDB或授权阶段码。
- 浏览器实测三尺寸首页（1280/390/320）、超长账号名称、文字不重叠、无横向溢出、首页打开/导出操作均通过。另有四尺寸聊天与四格式导出回归。
- 截图 `docs/images/home-desktop.png` / `home-mobile.png` 是已审查的12条虚构示例，不含真实账号。

## 本地详细AI资料包

实现 `python -m wechat_export.ai_bundle --archive ... --output ... --scopes ...`，范围通过私有JSON指定，不能空选变全量。

- 一次流式遍历原始JSONL，按明确会话ID分流；与索引计数及源哈希核对。
- 每个范围单独ZIP和同名目录：分析JSONL、Markdown/JSONL分卷、会话表、字段统计、范围/缺失说明、SHA256清单。
- 分卷最多1000条、目标约2MiB；单条超长消息完整保留，不截断。不是按token限制，使用者仍需匹配AI实际容量。
- ZIP只含分析资料；本地`raw-local-only/messages.jsonl`逐条保留原档案字段，不放进ZIP。
- JSONL保留时间、发送者、会话、来源定位、记录ID、类型、解析状态、原网页URL及附件引用核算。Markdown便于阅读；引用/转发卡片预览可能有界，完整结构仍在本地原始版。
- ZIP CRC及成员SHA256验证；ZIP的SHA清单仅列包内文件，本地清单还列原始版。原档案不改，输出目录exclusive创建并在同文件系统原子发布。
- 不包含附件二进制；不承诺手机历史全量。`source_kind=live-db`、`backup2_coverage=unverified`保留。
- 本次三个真实范围已本地生成并核对。数量和文件路径仅写私有交付报告与用户说明，不上传聊天/姓名/原始资料。
